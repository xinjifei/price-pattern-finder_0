# 收盘价形态识别与分析

> 一个从收盘价序列中识别形态，并继续检查形态后续表现的个人研究项目。

## 项目介绍

这个项目把图形直觉拆成可以运行和检查的数据流程：先在历史收盘价中寻找符合规则的窗口，再保存命中位置、评分和分段特征，最后由独立的分析模块研究这些命中之后发生了什么。

项目的重点不是直接给出交易结论，而是练习如何定义形态、检查识别结果、构造可比较的数据，并为分析结论保留清楚的适用边界。

## 工作流程

```text
原始收盘价
    ↓
滑动窗口与分段拟合
    ↓
规则筛选、特征评分与重叠去重
    ↓
生成结构化命中数据
    ↓
在 analysis/ 中进行独立分析
    ↓
结合输出解释结果与局限
```

识别、绘图和分析彼此分开：识别模块负责产生样本，绘图模块负责检查形态，分析模块负责回答具体研究问题。这样可以调整其中一个环节，而不必把整个项目重写。

## 仓库结构

```text
found_0/
├── data/              # 原始收盘价 CSV
├── analysis/          # 独立分析及其共用中间数据
├── plan/              # 设计记录与范围说明
├── check/             # 原始序列的交互式检查产物
├── tmp/               # 形态识别的临时诊断图
├── finder.py          # 形态识别、评分与去重
├── main.py            # 批量运行入口
├── plot.py            # 形态命中绘图
└── plot_data.py       # 原始收盘价检查图
```

`analysis/` 中每个研究问题使用独立子目录；多个分析共用的中间结果放在 `analysis/data/`。具体分析的输入、输出和运行方式以该目录中的说明为准。

## 数据约定

`data/` 中每份 CSV 代表一个标的，至少包含：

```text
date,close
```

- `date`：按时间排列的交易日期。
- `close`：对应日期的收盘价。

形态位置使用数据行索引记录，因此更新或替换原始数据后，需要重新生成命中数据，再运行下游分析。

## 使用方法

项目使用 Python 3.10+，依赖由 [uv](https://docs.astral.sh/uv/) 管理：

```bash
uv sync
uv run python main.py
```

需要检查完整收盘价序列时运行：

```bash
uv run python plot_data.py
```

下游研究进入相应的 `analysis/` 子目录，按该分析声明的输入和输出运行。

## 研究边界

- 形态评分衡量的是与当前规则的匹配程度，不自动等于未来收益预测能力。
- 历史样本中的描述性结果不能直接解释为因果关系或未来保证。
- 分析结论依赖数据范围、样本生成规则、比较口径和对照方式；这些条件需要随结果一起说明。
- 参数和研究问题可以继续变化，原始数据、命中数据与分析结论应始终保持可追溯。
